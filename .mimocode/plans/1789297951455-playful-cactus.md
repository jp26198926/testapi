# Mobile Responsive Refactoring Plan

## Overview
Make all 16 pages and shared components in the testapis project fully mobile-responsive using Tailwind CSS v4 responsive prefixes. No new dependencies. No design or functionality changes.

---

## Phase 1: Shared Components & Layouts (Fix Once, Benefits Everywhere)

### 1.1 Dashboard Layout — Add Hamburger Menu
**File:** `app/(dashboard)/layout.tsx`

**Problem:** Mobile header (`md:hidden`) only shows first 4 nav items. Items 5+ (Public API, Documentation, Billing, Settings) are completely inaccessible on mobile.

**Fix:**
- Replace the mobile header's horizontal-scroll nav with a hamburger menu button + slide-out mobile drawer
- Add `useState` for `mobileMenuOpen`
- Mobile drawer: full-height overlay from left, same nav items as sidebar, active state highlighting, sign-out button at bottom
- Close drawer on navigation (use `usePathname` change or click handler)
- Ensure the hamburger button and app name remain visible in the mobile header

**Pattern:**
```
<header className="md:hidden">
  <div className="flex items-center justify-between px-4 py-3">
    <Link>{appName}</Link>
    <button onClick={toggle}>☰</button>
  </div>
</header>

{mobileMenuOpen && (
  <div className="fixed inset-0 z-50 md:hidden">
    <div className="fixed inset-0 bg-black/50" onClick={close} />
    <div className="fixed inset-y-0 left-0 w-64 bg-white dark:bg-zinc-950 border-r ...">
      <nav>...all nav items...</nav>
      <div>...user email + sign out...</div>
    </div>
  </div>
)}
```

### 1.2 DocsNav Component — Add Mobile Hamburger
**File:** `components/docs-nav.tsx`

**Problem:** Nav links (`flex items-center gap-4`) overflow on narrow screens. No mobile toggle.

**Fix:**
- Hide links below `md:` breakpoint
- Add a hamburger button visible below `md:`
- Show links in a mobile dropdown/drawer when toggled
- Keep current desktop layout unchanged

### 1.3 Landing Page Header — Add Mobile Hamburger
**File:** `app/(landing)/page.tsx`

**Problem:** Header nav (Public API, Docs, Sign in, Get started) has no mobile adaptation. Links may overflow on small screens.

**Fix:**
- Hide the `div` containing nav links below `md:` breakpoint
- Add hamburger button visible below `md:`
- Mobile menu: vertical dropdown below the header bar with all links stacked
- Close on link click

### 1.4 Public API Page Header — Same Pattern
**File:** `app/public-api/page.tsx`

**Problem:** Same as landing page header.

**Fix:** Same hamburger menu pattern as 1.3.

### 1.5 Public Docs Page Header
**File:** `app/public-docs/page.tsx`

Uses `<DocsNav />` component, so fixing DocsNav (1.2) handles this.

## Phase 3: Forms & Inputs

### 3.1 Collection Detail Form Field Rows
**File:** `app/(dashboard)/collections/[collectionId]/page.tsx` (lines 318-341)

**Current:** `flex items-center gap-2` with `w-1/3` key input + `flex-1` value input. Doesn't wrap.

**Fix:** Change to `flex flex-col gap-2 sm:flex-row sm:items-center`. On mobile, key and value stack vertically. On `sm+`, they sit side by side.

### 3.2 Playground Method/Endpoint Row
**File:** `app/(dashboard)/playground/page.tsx` (lines 121-138)

**Current:** `flex gap-2` with select + input. No wrapping.

**Fix:** Add `flex-wrap sm:flex-nowrap` and ensure the select has a fixed width that doesn't shrink too small. On very narrow screens, the endpoint input takes full width below the select.

### 3.3 Playground Buttons Row
**File:** `app/(dashboard)/playground/page.tsx` (lines 179-203)

**Current:** `flex gap-2` with Send, Clear, Copy cURL buttons.
**Fix:** Add `flex-wrap` so buttons wrap on narrow screens.

### 3.4 Collection Detail Page Header Row
**File:** `app/(dashboard)/collections/[collectionId]/page.tsx` (lines 266-277)

**Current:** `flex items-center gap-4` with Back link, title, and Add Record button.
**Fix:** Add `flex-wrap` and ensure the button doesn't push content off-screen. Use `ml-auto` already present, but add `shrink-0` to the button.

## Phase 6: Global Overflow Prevention

### 6.1 Add `overflow-x: hidden` on `<html>` in globals.css
**File:** `app/globals.css`

Add `overflow-x: hidden` to `html` element as a safety net to prevent any accidental horizontal page scroll. This is a defensive measure, not a substitute for fixing layout issues.

```css
html {
  overflow-x: hidden;
}
```
