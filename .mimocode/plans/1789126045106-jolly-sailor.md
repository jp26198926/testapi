# Plan: Admin Settings Page with App Config, Cloudinary Upload, and Plan CRUD

## Goal
Create an admin-only `/settings` page where the admin can:
1. Update app name, logo, and favicon (with Cloudinary file upload)
2. Manage plans (add/edit/remove/toggle) — inactive plans hidden from landing page

---

## Step 1: Install Cloudinary SDK
```bash
npm install cloudinary
```

## Step 2: DB Schema — New Tables

**File:** `lib/db/schema.ts`

### `site_settings` table (single-row key-value or single-row table)
| Column | Type | Notes |
|--------|------|-------|
| `id` | uuid | PK, default random |
| `appName` | text | NOT NULL, default "TESTAPI" |
| `logoUrl` | text | nullable |
| `faviconUrl` | text | nullable |
| `updatedAt` | timestamp | NOT NULL, default now() |

### `plans` table
| Column | Type | Notes |
|--------|------|-------|
| `id` | uuid | PK, default random |
| `name` | text | NOT NULL (e.g. "Free", "Pro") |
| `price` | text | NOT NULL (e.g. "$0/mo", "$9/mo") |
| `features` | jsonb | NOT NULL, array of strings |
| `isActive` | boolean | NOT NULL, default true |
| `sortOrder` | integer | NOT NULL, default 0 |
| `createdAt` | timestamp | NOT NULL, default now() |
| `updatedAt` | timestamp | NOT NULL, default now() |

Generate migration with `npx drizzle-kit generate` and push.

## Step 3: Seed Default Data
Create a seed script or run inline SQL to insert:
- One `site_settings` row: `appName = "TESTAPI"`
- Two `plans` rows: Free ($0/mo, active, sortOrder=0), Pro ($9/mo, active, sortOrder=1) with current feature lists

## Step 4: Cloudinary Upload Utility

**New file:** `lib/cloudinary.ts`
- Configure Cloudinary SDK with env vars (`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`)
- Export `uploadImage(buffer: Buffer, folder: string)` — returns `{ url, publicId }`

**New API route:** `app/api/upload/route.ts` (POST)
- Admin-only endpoint
- Accepts `multipart/form-data` with an `image` field
- Validates file type (image/*) and size (max 2MB)
- Uploads to Cloudinary, returns `{ data: { url } }`

## Step 5: Admin Check Utility

**New file:** `lib/api/admin.ts`
- Export `isAdmin(user: User): boolean` — checks `user.email === process.env.ADMIN_EMAIL`
- Export `requireAdmin(user: User): void` — throws `AuthError("Admin access required.", 403)` if not admin

**New API route:** `app/api/admin/check/route.ts` (GET)
- Returns `{ data: { isAdmin: true/false } }` for the authenticated user
- Used by the client to conditionally show/hide Settings nav item

## Step 6: API Routes

### `app/api/settings/route.ts`
- **GET**: Public (no auth) — returns site settings (app name, logo, favicon) for use in layouts
- **PATCH**: Admin-only — updates `site_settings` row

### `app/api/plans/route.ts`
- **GET**: Public — returns active plans (`isActive = true`) sorted by `sortOrder`
- **GET** with `?all=true`: Admin-only — returns all plans
- **POST**: Admin-only — create a plan

### `app/api/plans/[planId]/route.ts`
- **PATCH**: Admin-only — update a plan
- **DELETE**: Admin-only — delete a plan

## Step 7: Settings Page UI

**File:** `app/(dashboard)/settings/page.tsx` (rewrite)

Admin-only page with two sections:

### Section 1: App Settings
- App Name: text input
- Logo: file upload with preview (uses Cloudinary upload endpoint)
- Favicon: file upload with preview
- Save button → PATCH `/api/settings`

### Section 2: Plans Management
- Table/cards listing all plans (active + inactive)
- Each plan shows: name, price, features, active toggle switch
- Add Plan button → modal/form to create new plan
- Edit/Delete each plan
- Toggle switch → PATCH plan's `isActive`

### Admin guard
- On mount, fetch `/api/admin/check` — if not admin, show "Access Denied"
- Keep existing account info display for non-admin users (or redirect)

## Step 8: Landing Page — Dynamic Plans

**File:** `app/(landing)/page.tsx` (convert to client component or use server-side DB query)

- Fetch plans from `/api/plans` (returns only active plans)
- Render dynamically instead of hardcoded Free/Pro cards
- If no plans are active, show no plans section

## Step 9: Dashboard Layout — Conditional Settings Nav

**File:** `app/(dashboard)/layout.tsx`

- Fetch admin status (from `/api/admin/check` or a prop)
- Conditionally include "Settings" in `NAV_ITEMS` only for admins

## Step 10: App Name Everywhere

Replace hardcoded `"TESTAPI"` with the settings value in:
- `app/layout.tsx` — metadata title
- `app/(dashboard)/layout.tsx` — sidebar brand
- `app/(landing)/page.tsx` — header/footer
- `app/(auth)/login/page.tsx` and `register/page.tsx`
- `app/public-api/page.tsx`

These will need to either:
- Fetch settings server-side (for Server Components)
- Use a shared context/provider (for Client Components)
- Or fetch from the `/api/settings` endpoint
