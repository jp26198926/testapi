# Playground Page Fix Plan

## Root Cause

The playground body placeholder says `{"key": "value"}` but the API expects `{ "data": { "key": "value" } }`. The Zod schemas (`createRecordSchema`, `updateRecordSchema`) both require a `data` wrapper object — without it, `body.data` is `undefined`, producing: `"expected record, received undefined"`.

Additionally, the playground provides no guidance on which endpoints to use, what methods each endpoint supports, or the correct URL format. The default endpoint `/api/public/posts` only supports GET, but the user might try POST/PUT/PATCH/DELETE on it.

## Changes — single file

**File:** `app/(dashboard)/playground/page.tsx`

### 1. Fix body placeholder

Change the body textarea placeholder from:
```
{"key": "value"}
```
to:
```
{"data": {"key": "value"}}
```

### 2. Add default body content for POST/PUT/PATCH

When the user switches to a write method, pre-fill the body textarea with a valid example:
```json
{"data": {"title": "Hello", "content": "World"}}
```
This prevents the "empty body" case where body is `""` and `JSON.parse("")` fails before even reaching the API.

### 3. Add a collapsible API Reference section below the request panel

Show a reference of available endpoints, their supported methods, and example body format:

| Method | Endpoint | Body |
|--------|----------|------|
| GET | `/api/public/{slug}` | - |
| GET | `/api/collection/{collectionId}/{slug}` | - |
| POST | `/api/collection/{collectionId}/{slug}` | `{"data": {...}}` |
| GET | `/api/collection/{collectionId}/{slug}/{recordId}` | - |
| PUT | `/api/collection/{collectionId}/{slug}/{recordId}` | `{"data": {...}}` |
| PATCH | `/api/collection/{collectionId}/{slug}/{recordId}` | `{"data": {...}}` |
| DELETE | `/api/collection/{collectionId}/{slug}/{recordId}` | - |

### 4. Validate JSON body before sending

Add a check: if the method is POST/PUT/PATCH and body is non-empty, `JSON.parse(body)` first. If it fails, show an inline error "Invalid JSON in request body" instead of sending the request.

### 5. Update Copy cURL to include proper headers

The cURL command should include `-H 'Content-Type: application/json'` for write methods.
