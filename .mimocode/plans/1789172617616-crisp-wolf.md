# Admin Unlimited Access

## Problem
Admin users are subject to the same collection limits, record limits, and rate limits as free users. Admin should have unlimited access to everything.

## Files to modify

### 1. `lib/api/plans.ts`

Import `isAdmin` from `./admin`. Add admin bypass at the top of `canCreateCollection()` and `canCreateRecord()`:

```ts
export async function canCreateCollection(userId: string): Promise<boolean> {
  // Need to fetch user to check admin — but we don't have the user object here.
  // Instead, accept an optional user param or check admin by userId.
}
```

Actually, `isAdmin()` takes a `User` object (needs `email`), not a userId. The cleanest approach: add a helper `isAdminById(userId)` that queries the DB for the user's email and checks against `ADMIN_EMAIL`.

**Simpler approach:** Just pass the user object into `canCreateCollection` and `canCreateRecord`. The callers already have the user from `requireAuth()`.

Changes:
- Import `isAdmin` from `./admin` and `User` type from `better-auth`
- `canCreateCollection(userId)` → `canCreateCollection(userId: string, user?: User)` — if `user && isAdmin(user)` return `true` immediately
- `canCreateRecord(userId, collectionId)` → `canCreateRecord(userId: string, collectionId: string, user?: User)` — same admin bypass
- Update callers in `POST /api/collection` and `POST /api/collection/[id]/[slug]` to pass `user`

### 2. `lib/api/rate-limit.ts`

Add an `"admin"` tier with effectively unlimited requests:

```ts
admin: { max: 100_000, windowMs: 60_000 },
```

### 3. `app/api/collection/route.ts` (POST)

Import `isAdmin`. Change rate limit call from hardcoded `"free"` to dynamic:
```ts
const tier = isAdmin(user) ? "admin" : "free";
const rl = checkRateLimit(user.id, tier);
```

Pass `user` to `canCreateCollection(user.id, user)`.

### 4. `app/api/collection/[collectionId]/[slug]/route.ts` (POST)

Same pattern — dynamic tier, pass user to `canCreateRecord`.

### 5. `app/api/keys/route.ts` (POST)

Same pattern — dynamic tier for rate limit.

---

## Verification

1. Log in as admin → create > 5 collections → should succeed (no limit)
2. Create > 50 records in a collection → should succeed (no limit)
3. Send many rapid requests → no rate limit hit
4. Log in as free user → limits still enforced normally
5. `npm run build` passes
