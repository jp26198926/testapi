# Fix: Upgrade button does nothing

## Diagnosis (step by step)

1. Click **Upgrade to Pro** → `handleUpgrade(p.id)` in `app/(dashboard)/billing/page.tsx`
2. `POST /api/subscriptions` with `{ planId: "<pro uuid>" }`
3. Route looks up that plan’s `paypalPlanId` — **all plans have `paypal_plan_id = null`**
4. Env fallback `PAYPAL_PLAN_ID` is also **unset**
5. `createSubscription()` throws: `"No PayPal plan configured. Set plans.paypalPlanId or PAYPAL_PLAN_ID."`
6. API returns `400 { error: { message } }`
7. UI only redirects when `result.data?.approvalUrl` exists; errors are swallowed (`catch {}` / no error state)

**DB (verified):** Free/Pro/Plus all have `paypal_plan_id: null`  
**Env (verified):** client id + secret + webhook id present; `PAYPAL_PLAN_ID` missing

## Fix

### 1. Surface upgrade errors in the billing UI

**File:** `app/(dashboard)/billing/page.tsx`

- Add `const [upgradeError, setUpgradeError] = useState("")`
- In `handleUpgrade`:
  - clear error at start
  - if `!res.ok` or `result.error?.message` → `setUpgradeError(...)` and return (no silent fail)
  - only redirect when `result.data?.approvalUrl` is present
- Render a red error banner near the plans / current plan card

### 2. Configure a PayPal subscription plan id (required for real upgrades)

Either:

**A. Env (quick sandbox)**
```
PAYPAL_PLAN_ID=P-xxxxxxxx
```
(Create a subscription plan in PayPal sandbox Dashboard → Products → Subscription plans → copy id)

**B. DB (preferred, matches “link plans to PayPal”)**
```http
PATCH /api/plans/b5e2405a-a567-40cc-a641-e3983e362be6
Authorization: <admin session cookie>
Content-Type: application/json

{ "paypalPlanId": "P-xxxxxxxx" }
```
(Pro plan id from DB: `b5e2405a-a567-40cc-a641-e3983e362be6`)

Restart dev server after env change.
