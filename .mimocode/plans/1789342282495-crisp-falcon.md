# Fix: Favicon not applying after PNG upload

## Diagnosis

**PNG is not the problem.** Modern browsers accept PNG favicons, and Next 16 supports external absolute URLs in `metadata.icons`.

Likely causes (in order):

1. **Stale-while-revalidate** — `revalidateTag("site-settings", "max")` serves the old cached settings (no favicon) on the first request after save, then refreshes in the background. Logo still works because client pages fetch live `/api/settings`; favicon comes from server `generateMetadata` + `unstable_cache`.
2. **Browser favicon cache** — browsers cache tab icons aggressively; a normal refresh often keeps the old (missing) icon.
3. **Metadata `icons` injection** — Next recommends the file-based icon route; config-based `icons` can be less reliable, especially with dynamic external URLs.

## Fix

Use the file-based `app/icon.tsx` route (Next auto-injects `<link rel="icon" href="/icon">`) and make admin saves invalidate immediately.

### 1. Create `app/icon.tsx`

Dynamic route that reads `faviconUrl` from settings and proxies the image from Cloudinary:

```tsx
import { getSiteSettings } from "@/lib/settings";

export const size = { width: 32, height: 32 };
export const contentType = "image/png";

export default async function Icon() {
  const { faviconUrl } = await getSiteSettings();
  if (!faviconUrl) return new Response(null, { status: 404 });

  const res = await fetch(faviconUrl);
  if (!res.ok) return new Response(null, { status: 404 });

  const body = await res.arrayBuffer();
  return new Response(body, {
    headers: {
      "Content-Type": res.headers.get("content-type") || "image/png",
      "Cache-Control": "public, max-age=300, stale-while-revalidate=600",
    },
  });
}
```

Notes:
- Proxy (not redirect) — some browsers mishandle favicon redirects.
- 404 when unset — browser falls back to default; no broken icon.
- Keep `getSiteSettings` so cache/revalidate still applies.

### 2. Remove `icons` from `generateMetadata`

**File:** `app/layout.tsx`

Drop the `...(faviconUrl ? { icons: ... } : {})` spread so we don't emit two competing `<link rel="icon">` tags. Keep dynamic `title` from `appName`.

```ts
export async function generateMetadata(): Promise<Metadata> {
  const { appName } = await getSiteSettings();
  return {
    title: `${appName} — API Playground`,
    description: "...",
  };
}
```

### 3. Immediate cache bust on admin save

**File:** `app/api/settings/route.ts`

Change both calls from profile `"max"` (stale-while-revalidate) to immediate expiry:

```ts
revalidateTag("site-settings", { expire: 0 });
```

So the next page load after Save always reads fresh settings for title + icon.

## Verification

1. Restart `next dev` (icon route + config).
2. Confirm settings already have a saved `faviconUrl` (or re-upload PNG + Save).
3. Open `/` in a **private window** → tab shows the PNG; View Source / DevTools → Network has `GET /icon` returning `image/*`.
4. Replace favicon in admin → Save → reload private window → new icon (no 10‑minute delay).
5. Remove favicon → Save → `/icon` returns 404; browser default icon.
6. `npx tsc --noEmit` stays clean.

## Why not keep generateMetadata icons?

It can work, but Next docs prefer file-based icons; proxying via `/icon` avoids metadata injection edge cases and gives a stable URL browsers already request. Combined with `{ expire: 0 }`, admin changes show up immediately.
