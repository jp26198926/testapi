# Fix: Billing Records not refreshing + success+error after PayPal

## Diagnosis

1. **Billing Records stale** — after capture, `billing/page.tsx` calls `refetchSubscription()` and `fetchPaymentRecords()` but **not** `fetchBillingRecords()`. That table only reloads when page/limit change.
2. **Success + error together** — PayPal return `useEffect` can run twice (React Strict Mode / remount). Two `POST /api/billing/capture` calls race:
   - First succeeds → green success banner
   - Second fails (or returns an error body) → red error banner **while success stays visible**
   - Client never clears `upgradeError` when setting success

## Fix — `app/(dashboard)/billing/page.tsx` only

1. **Refetch billing records after capture**
   - Move `fetchBillingRecords` `useCallback` **above** the PayPal-return effect (it is currently defined after and cannot be called).
   - On capture success: `refetchSubscription()`, `fetchBillingRecords()`, `fetchPaymentRecords()`.
   - On success also `setUpgradeError("")`.

2. **Single-flight capture**
   - `const captureStartedRef = useRef(false)`
   - In the return effect: if `captureStartedRef.current` return; else set true and proceed.
   - Prevents double POST from Strict Mode double-mount.

3. **Banner exclusivity**
   - When setting `banner` to `"success"`, clear `upgradeError`.
   - When setting `upgradeError`, optionally leave banner null so only one shows.

No API changes required. Capture route is already idempotent.
